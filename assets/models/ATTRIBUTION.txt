PdfCraft's text recognition (Scan & OCR) uses the two text models, unmodified, and its scanner
finds the page in a photo with scan-edges.onnx.

text-detection.rten
  Ocrs text detection model
  by Robert Knight (ocrs-models; trained on HierText, CC-BY-SA-4.0)
  from https://github.com/robertknight/ocrs-models (the models ocrs downloads; model card: https://huggingface.co/robertknight/ocrs, cc-by-sa-4.0)
  licence: CC-BY-SA-4.0 (https://creativecommons.org/licenses/by-sa/4.0/legalcode.txt; full text in text-detection.rten.LICENCE.txt)

text-recognition.rten
  Ocrs text recognition model
  by Robert Knight (ocrs-models; trained on HierText, CC-BY-SA-4.0)
  from https://github.com/robertknight/ocrs-models (the models ocrs downloads; model card: https://huggingface.co/robertknight/ocrs, cc-by-sa-4.0)
  licence: CC-BY-SA-4.0 (https://creativecommons.org/licenses/by-sa/4.0/legalcode.txt; full text in text-recognition.rten.LICENCE.txt)

scan-edges.onnx
  DocQuadNet-256, the document corner detection model of MakeACopy
  by Christian Kierdorf (Copyright 2026; trained on UVDoc, SmartDoc 2015, DTD backgrounds and CORD, none of which is redistributed)
  from https://github.com/egdels/makeacopy at commit 7f2edaca025944194309328d9c6f69b7337e0533, file app/src/main/assets/docquad/docquadnet256_trained_opset17.ort (SHA-256 f0f2f52d7d79ff02d346c8f9d0c9e903407366aeea1747cdcff160c401e3e72a)
  changed: the same network and weights, stored differently. The upstream file is in ONNX Runtime's own format; tools/scan-models/ort_to_onnx.py writes it back as plain ONNX (outputs equal to 2e-5) and tools/scan-models/to_fp16.py stores the weights as 16-bit floats.

# PdfCraft Android 0.0.20-beta (20012)

## New features

- No new user-facing tools in this maintenance release. Existing annotation and editing tools remain available.

## Fixes

- **Avoid repeated form discovery during opening:** When comment appearance preparation leaves the source unchanged, opening reuses the form-field discovery already needed for display instead of scanning every page again for the document model. This also helps eligible PDFs with many links and no form fields.
- When comment appearances change the display document, opening keeps separate discovery for the overlay and original source. Field values, adopted widgets, script-button handling, signatures and saved source bytes keep their existing behavior.

## Improvements

- Opt-in open diagnostics add `native_display_form_discovery` inside `native_display`. The later `native_form_fields` stage can be zero because discovery was reused. Nested stages overlap and must not be added together.
- A controlled synthetic host comparison measured median native preparation of 398 to 312 ms for ordinary link objects and 367 to 311 ms for compressed link objects across three opens per case. These measurements are illustrative host results, not Android speed guarantees. Details are in `docs/performance/open-field-discovery.md`.

## Known limits and testing

- This removes one eligible duplicate pass. Full document inspection, signature discovery, appearance preparation and the native file read still happen before the first page. Comment-overlay cases deliberately retain fresh discovery. Opening is not progressive.
- The change has not been measured on a physical Android device and does not establish that opening a particular large PDF is fixed.
- PR #221 passed exact-head Rust/provenance, Android JVM, merge-gate and title checks. Locally, 2,672 tests passed across the parser, signature, forms, engine, renderer, automation and mobile suites, with 8 existing ignored tests. Regressions cover rendering, saved bytes, field values, widget adoption and comment-overlay fallback.
- Publication additionally requires release CI and permanent-signing, package, actual APK manifest and checksum verification. Earlier beta limitations remain applicable; this release does not claim complete desktop parity or device validation.

## Installing

Install `pdfcraft-android-0.0.20-beta.apk` (arm64-v8a) from the official GitHub Release or the in-app updater after publication. The verified manifest must show `0.0.20-beta (20012)`. It updates 0.0.19-beta (19012) with the same application ID and permanent owner signing certificate. Android still asks for installation approval. Earlier published APKs remain unchanged.

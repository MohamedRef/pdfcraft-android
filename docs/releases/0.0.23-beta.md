# PdfCraft Android 0.0.23-beta (23012)

## New features

- **Large files are no longer copied into memory to open:** A PDF of at least 1 MiB in PdfCraft's own private document store is now read through a read-only memory mapping, shared by both PDF readers, the renderer and editing history, instead of a full in-memory copy. Files elsewhere, shared files and any case the safety checks do not accept keep the previous bounded copy. The open timings show which path was used (`native_input_mapped` or `native_input_owned`).

## Fixes

- **No second parse for the first page:** The reading stage already parses the file to get exact page sizes. That parse is now kept and used for the first page render, which before parsed the same file again (about 60 ms of the 135–210 ms first render on a Galaxy S24 Ultra in 0.0.22).

## Improvements

- **Reading-stage checks and page sizes in parallel:** The page-size parse and the checks that decide whether a page can be shown early now run side by side; the checks still decide first, in the same order.
- **More detailed open timings:** New stages `native_reading_fields`, `native_reading_pages`, `native_reading_page_check` and `native_reading_build` show where the reading-stage preparation goes. Thumbnails of large local files use a separate 100 MiB input limit, so listing them does not make another full copy.

## Known limits and testing

- On 0.0.22-beta (22012), on the owner's Galaxy S24 Ultra with a 352 MB, 869-page PDF, the first page appeared after 0.47–0.78 s and editing was ready after 2.1–2.3 s. The 0.0.23 changes target the file read (0.16–0.38 s there), the reading preparation (0.13–0.21 s) and the first render; their effect on a phone has not been measured yet.
- Mapping avoids the whole-file allocation but not page faults; signature hashing and full preparation may still touch every page of the file. No fixed opening time or memory saving is promised. The mapping relies on PdfCraft writing its stores only by atomic replacement (audited in #228 and #230).
- Full preparation (inspection about 1.2 s and signature discovery about 0.9 s on that phone, in parallel) is unchanged in this release; editing, saving and signature status still wait for it.
- Automated Rust/provenance (including mapped/owned differential tests and pixel equality for the reused first-page parse), Android JVM and signed ARM64 release checks passed. Not yet verified on a physical device.

## Installing

After the source, test, release-signing, ABI, manifest and checksum gates succeed, the in-app updater offers `pdfcraft-android-0.0.23-beta.apk` (arm64-v8a) from the official PdfCraft Android fork's GitHub Release. You can also download it there. Check that the SHA-256 and the manifest version `0.0.23-beta (23012)` match, then approve the installation in Android. It installs over 0.0.22-beta (22012) with the same package and signing certificate; earlier releases are not replaced.

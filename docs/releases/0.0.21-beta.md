# PdfCraft Android 0.0.21-beta (21012)

## New features

- **Read eligible large PDFs before full preparation finishes:** Ordinary page viewing can show a read-only reading stage with exact page dimensions and original page artwork, then finish metadata, signatures and editing preparation in the background after the first canvas submission. A visible status explains that editing and signature information are still being prepared.

## Fixes

- **Closing and replacing a document:** Pending preparation is cancelled at native stage boundaries. Late results cannot revive a closed handle, replace a ready document or restore a renderer cache for an obsolete source.
- **Keep uncertain information explicit:** While preparation is pending, signature and properties panels show preparation status. Native editing, saving, printing and copying remain unavailable until the complete document is ready. Source bytes are unchanged by the reading stage.

## Improvements

- Preserve the document id, exact page geometry and viewport when full preparation becomes available, and advance the page/link cache generation safely.
- Diagnostics distinguish `native_reading_ready` from full `native_ready`. In a warmed synthetic host comparison using a 356 MB, 869-page PDF with 27,808 links, median time to first raster was 207 ms through the reading stage versus 715 ms through complete opening over three paired trials. These host measurements are not Android performance guarantees or GPU presentation timings. Details are in `docs/performance/progressive-reading-open.md`.

## Known limits and testing

- Android selects the reading stage for eligible inputs of at least 16 MiB in ordinary page viewing, with no pending editing tool. Reopening directly into reflowed Reading Mode retains complete opening.
- Initial or restored pages with comments, widgets, unknown annotations or excessive annotation entries retain complete opening. Other complex pages wait until preparation is complete. XFA, nonempty/unreadable form-field trees, repaired sources and incompatible geometry/password cases also keep the existing complete path. Some large PDFs therefore retain their previous opening time.
- Signature discovery, validation and form adoption are still performed in full; their absence is never inferred from a missing AcroForm. Cancellation does not forcibly interrupt an active parser or signature operation. The full input copy remains in native memory.
- PR #223 passed exact-head Rust/provenance, Android JVM, title and merge-gate checks. Locally, 2,684 tests passed with 8 existing ignored tests, including 12 new regressions for rendered pixels, geometry, unchanged bytes, encrypted permissions, orphan/tree-listed widgets, standalone timestamps, fallback behavior, cancellation and late renderer caches.
- Performance and behavior have not yet been measured on physical Android hardware for this change. Publication additionally requires release CI, permanent signer, package, actual manifest build and checksum verification. Earlier beta limitations remain applicable.

## Installing

Install `pdfcraft-android-0.0.21-beta.apk` (arm64-v8a) from the official GitHub Release or the in-app updater after publication. The verified manifest must show `0.0.21-beta (21012)`. It updates 0.0.20-beta (20012) with the same application ID and permanent owner signing certificate. Android still asks for installation approval. Earlier published APKs remain unchanged.

# PdfCraft Android 0.0.19-beta (19012)

## New features

- **Detailed native open timings:** Settings → About → Diagnostics → Record open timings now breaks native opening into file reading, editing and rendering parsers, page geometry, document inspection and compatibility fallback, signatures, metadata, display preparation and form fields. Only fixed stage names and durations are added. Nested and parallel timings overlap and must not be added together. The repair count describes the editing parser, not every renderer fallback.

## Fixes

- **Faster stream recovery while opening some large PDFs:** When embedded data has a missing or inaccurate length, opening can search the entire file for stream endings during timestamp discovery, even in an unsigned PDF with zero repair notes. This search now uses a faster substring implementation while preserving PDF token boundaries, recovery results and signature validation. An approximately 352 MB / 869-page synthetic image book opened in 143 ms after the change, compared with 603 ms before it. These are host measurements, not phone results.

## Improvements

- **Less excess input-buffer reservation:** Reading a regular file uses its known size instead of repeatedly growing the buffer. A same-size synthetic read reserved about 336 MiB instead of 512 MiB on the host. This is buffer capacity, not an Android RAM or speed measurement; the full PDF is still read into native memory. The input size cap and file-access checks remain in place.
- Differential tests compare the new stream-ending search with the original across binary input, token boundaries and line endings. A manual synthetic benchmark and its limits are documented in `docs/performance/stream-end-open.md`.

## Known limits and testing

- The original slow document has not been inspected or reproduced, and performance on a physical Android device has not been measured. These changes do not establish that a particular phone's slow opening is fixed. Use the detailed open-timing report to identify its dominant stage.
- Opening still waits for the working copy, full native file read and document preparation before showing page 1. All-page links, comments and field preparation can remain expensive in heavily annotated documents; these are separate from stream-ending recovery.
- PRs #218 and #219 passed Rust/provenance, Android JVM and merge-gate checks. Local parser, signature, engine, renderer, automation and mobile suites passed 2,386 tests (8 existing ignored). Publication additionally requires the signed ARM64 APK, certificate, package, actual manifest build and checksum gates to succeed.
- Earlier beta limitations remain applicable. This release changes opening performance and diagnostics; it does not claim complete desktop feature parity or device validation.

## Installing

Install `pdfcraft-android-0.0.19-beta.apk` (arm64-v8a) from the official GitHub Release or the in-app updater after publication. The verified manifest must show `0.0.19-beta (19012)`. It updates 0.0.18-beta (18012) with the same application ID and permanent owner signing certificate. Android still asks for installation approval. Earlier published APKs remain unchanged.

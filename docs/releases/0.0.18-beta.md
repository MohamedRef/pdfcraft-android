# PdfCraft Android 0.0.18-beta (18012)

## New features

- **Open timings show repairs:** The open timings report (Settings → About → Diagnostics) now also records how many repairs a file needed while opening (`native_repairs`). A count only; the notes themselves are not recorded.

## Fixes

- **Large damaged PDFs open much faster:** When a file's cross-reference data is damaged, PdfCraft rebuilds it by scanning the whole file, and it did this slowly and twice in a row. The scan now looks for object headers directly, uses a faster search, and the two readers run at the same time. On a synthetic 380 MB / 869-page test file with a broken cross-reference, opening went from 3.7 s to 0.85 s on a 2-core test machine; a file without damage still opens in about 16 ms. This has not been measured on a phone yet.

## Improvements

- **No second copy of an unchanged file:** Opening a PDF from another app no longer copies the whole file into PdfCraft again when it has not changed since the last open (same size and modification date reported by the app it comes from, and PdfCraft's copy unchanged and complete). Such copies are kept for documents in Recent, up to 2 GB and never more than a quarter of the free space; the oldest go first.

## Known limits and testing

- The speed-up targets files that need repair. Whether the owner's 352 MB file is one is not yet confirmed: the new `native_repairs` line in the open timings will show it. If it reads 0, the slow open has another cause that is still open (#212).
- Two more full scans remain on damaged files (the renderer's own fallback and the compatibility reader); they are the rest of the 0.85 s.
- Reusing a copy relies on the other app reporting a size and a modification date; when it reports neither, the file is copied as before. An app that changes a file without changing either would reopen the older copy.
- Automated Rust/provenance (including a check that the new header scan finds exactly what the old one found), Android JVM and signed ARM64 release checks passed. Not tried on a physical device.
- All limits listed for earlier betas still apply; reviewer issues #70–#205 remain open.

## Installing

After the source, test, release-signing, ABI, manifest and checksum gates succeed, the in-app updater offers `pdfcraft-android-0.0.18-beta.apk` (arm64-v8a) from the official PdfCraft Android fork's GitHub Release. You can also download it there. Check that the SHA-256 and the manifest version `0.0.18-beta (18012)` match, then approve the installation in Android. It installs over 0.0.17-beta (17012) with the same package and signing certificate; earlier releases are not replaced.

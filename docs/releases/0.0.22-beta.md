# PdfCraft Android 0.0.22-beta (22012)

## New features

- Optional lower-memory page previews in Preferences. Opaque full pages use RGB565 before transfer to Android, halving their packed pixel data. Color precision is reduced; transparency and zoomed details retain full quality. The setting applies when reopening a document.

## Fixes

- Preserve an existing working copy if atomic publication of a new copy fails. Remove the fallback that could truncate an inode still used by a reader.
- Reject stale or closed-document overlay results and clear page metadata when its generation changes. Keep complete comment threads and cross-page form navigation available.
- Record a fixed diagnostic reason when an attempted reading stage falls back to complete opening. Tiny visible widgets, unknown locations, malformed trees and exhausted budgets remain conservative.

## Improvements

- Publish the viewer before loading all comments. Load visible-page comments and widgets in bounded batches; fetch complete comment lists and threads on demand.
- Batch comment-property lookup so the page tree is visited once and each selected annotation array is copied once per request, instead of repeating this work for every comment.
- Expand reading-stage eligibility for explicit null form entries, invisible signature widgets and fields on other pages, while retaining full signature discovery and validation.
- Prioritize visible pages and zoomed details over speculative rendering. Offscreen prefetch waits until 120 ms after the first canvas submission. Full preparation uses a separate low-priority worker.
- Request Android's large heap and size the page cache from the actual VM heap, with a bounded fraction and 192 MiB ceiling. Charge actual Bitmap allocations, including compact-row padding, to the cache.

## Known limits and testing

- Shared file-backed input and mmap integration are not included in this release. The current native input copy remains; the wider shared-input plan is unfinished. Atomic working-copy publication is a prerequisite, not evidence that every mapping lifetime is safe.
- Some PDFs still require complete preparation before viewing, including complex initial-page annotations, XFA, repairs, unknown widget locations and incompatible geometry/password cases. Signatures stay pending until complete discovery and validation; a missing AcroForm never proves absence.
- A large-heap request does not guarantee a particular device heap size. Compact previews trade color precision for memory and transfer size; normal previews remain the default.
- PRs #225, #226 and #227 require exact-head Rust/provenance, Android JVM, conventional-title and merge-gate success before merge. Regression coverage includes rendered pixels, immutable snapshots after close, bounded page requests, source preservation, batched annotation work, RGB565 packing/opacity fallback, exact tiles, heap budgets and render priority. Atomic-publication tests cover failure preservation, mapped readers and invalid staging paths.
- These changes have not been measured or manually verified on physical Android devices. No phone opening-time or RAM-saving percentage is promised. Release publication additionally verifies the permanent signing identity, package, actual manifest build and checksum.

## Installing

Install `pdfcraft-android-0.0.22-beta.apk` (arm64-v8a) from the official GitHub Release or in-app updater after publication. The verified manifest must show `0.0.22-beta (22012)`. It updates 0.0.21-beta (21012) using the same application ID and permanent owner signing certificate. Android asks for installation approval. Earlier published APKs remain unchanged.

# PdfCraft Android 0.0.9-beta.2 (9022)

This is the first Android prerelease containing the complete three-feature S Pen batch. The signed ARM64 package is intended for Samsung Galaxy S24 Ultra and Galaxy Tab S11, subject to Android compatibility.

## New features

- **Pressure-sensitive S Pen ink** ([#19](https://github.com/MohamedRef/pdfcraft-android/pull/19)): capture pen pressure for varying on-screen stroke width and approximate it in editable PDF Ink annotations.
- **Real Ink Eraser** ([#20](https://github.com/MohamedRef/pdfcraft-android/pull/20)): erase affected sections of editable Ink annotations using the Draw Eraser tool, with native undo/redo. Locked ink and signatures are not targeted.
- **S Pen Hover and Historical Input** ([#21](https://github.com/MohamedRef/pdfcraft-android/pull/21)): show a non-editing cursor while the stylus hovers over the page; process bounded intermediate stylus points for smoother captured lines.

## Fixes and improvements

- Bound allocations from untrusted batched pen movement to avoid unnecessary memory growth, deduplicate/validate intermediate points, and keep movement in time order.
- Preserve existing finger navigation and palm rejection routing, S Pen button/eraser handling, document signing, editable annotations, forms, and the secure SAF working-copy and recovery model.

## Important known issues and validation limits

- **PDF opening speed is still an outstanding issue.** Especially on large files, PdfCraft can remain noticeably slower than Xodo; previous changes have **not** been validated as a speed improvement on the user's device. A separate performance/profiling PR is planned after this release.
- **S Pen device behavior is not physically validated** on Samsung Galaxy S24 Ultra or Tab S11. Automated Rust, provenance and Android JVM tests pass, but pressure response, button/eraser-tip mapping, hover, palm rejection, and save/reopen must still be tested on actual devices.
- Historical point pressure is **interpolated**, because the Compose HistoricalChange interface provides position and time, not per-sample hardware pressure. PDF variable-width ink uses an approximate set of editable Ink segments rather than one native pressure-variable object.
- The Android SAF file-provider lifecycle and encrypted/large PDF first-page latency have not been device-benchmarked in this release. No 100% hardware compatibility, first-page acceleration or Xodo parity is claimed.

## Installing

The signed `arm64-v8a` APK uses the existing app ID `io.github.mohamedref.pdfcraft`. Check the accompanying `.sha256` file and approve installation in Android; no silent installation is performed. The actual APK manifest must report version `0.0.9-beta.2 (9022)`. Older signed releases remain available.

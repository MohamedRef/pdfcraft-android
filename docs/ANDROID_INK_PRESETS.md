# Favorite pen presets

## Unlimited favorites, recent colours, hex entry, finer widths (#149)

Favorites are one list (`ink.presets.v2`, up to 48 entries) instead of three fixed slots; the three old `ink.preset.v1.N` slots seed the list once. In Pen settings, **Add current pen** appends the selected pen; a long press on a favorite offers Replace with current pen, Move earlier, Move later and Delete. The pen popover shows the last eight ink colours (`ink.recentColors`), each announced by its hex value, and a hex field that accepts `#RRGGBB` or `#AARRGGBB` and rejects anything else with a message. Pen widths now range from 0.1 to 20 pt in 0.1 pt steps. **Pick colour from page** in the pen popover arms an eyedropper: the next tap takes the exact colour of the nearest unsaved stroke, or of the saved ink (else other coloured comment) under the finger.

## Palettes and custom colours (#149)

The pen style sheet chooses which palette it shows: **Standard** (the 18 comment swatches), **Colour-blind safe** (the eight Okabe–Ito colours, each with a spoken name) or one of the user's own named palettes (`ink.palettes.v1`, up to 32 palettes of up to 64 colours). **New palette** starts a palette from the current pen colour; **Add current colour** adds to the shown palette; a long press on a colour removes it (TalkBack offers the same as a custom action). **Export** saves the palette as a small JSON file (`{"format":"pdfcraft-ink-palette","version":1,"name":…,"colors":[{"color":"#AARRGGBB","name":…}]}`) through the system's file picker, and **Import palette** reads one back: files over 64 KB, files of another format or a newer version, and files with no valid colour are refused with a message; bad colours are skipped, names are cleaned and shortened to 60 characters, and a name already in use gets a number. **Custom colour…** opens a saturation/brightness square and a hue slider; the pen takes the colour when a tap, drag or slide ends, so a drag does not fill the recent colours with in-between steps.

## Per-pen settings (#187, #188)

Each of the five pens (Ball, Fountain, Pencil, Brush, Marker) keeps its own colour, width and opacity under `ink.<style>.color`, `ink.<style>.width` and `ink.<style>.opacity`. Switching pens never restyles another pen, and each toolbar nib preview shows its own pen's colour and width. Fresh installs start from per-pen defaults (black ball, blue fountain, grey pencil, red brush, wide yellow marker). On the first launch after the update, the old shared `ink.color`/`ink.width`/`ink.opacity` move to the pen that was last used, so that pen looks the same; the migration is written immediately so it does not move again. A favorite is a full snapshot: using it restyles its own pen type and selects it.

Tapping the already selected pen opens a compact popover with that pen's width chips, a half-point slider, colours and opacity (the same second-tap pattern as the eraser size). The row-2 button is now **Settings** (sheet title **Pen settings**) and holds only Pen only, Snap to shape and favorites; the duplicated pen-style row, thickness, colour and opacity were removed from it.

Draw → Favorite pens offers three persistent slots containing ink color, width and opacity. Use pen applies the selected appearance; Replace with current pen explicitly saves the current drawing settings into that slot. Author, pen-only routing, pressure/history/hover, eraser mode and snap-to-shape remain independent. Existing strokes and PDF contents are not edited by choosing a favorite.

## Persistence and input boundaries

Each slot uses a bounded, versioned preferences string. Malformed/unknown/oversized values, invalid ARGB, non-finite widths/opacities and values outside existing mobile UI ranges fall back to that slot's factory preset. Existing global drawing preferences remain compatible. Saving a slot changes only that preset key; using it writes ink color/width/opacity in one preferences transaction. No document path, author or personal text is serialized in a profile.

The Draw layer's existing immutable appearance snapshot at stroke start is unchanged, so completed/in-progress stroke appearances are not retroactively changed by later settings. The preset picker scrolls for compact windows; the Draw toolbar already scrolls horizontally.

## Verification

JVM cases cover ARGB/width/opacity round-trips, corrupted/future/oversized/non-finite data and locale-independent storage. Existing ink appearance, pressure, stylus routing/history and eraser regressions remain intact. Current-head Rust/provenance, Android JVM/ARM64 bindings, title and aggregate gate are required before merge. Physical S Pen behavior, app restart, RTL/accessibility, DeX/landscape and switching favorites during drawing still need device QA. These presets are one part of the larger stylus backlog, not full Xodo parity.

## S Pen side button (#144)

**One line, not a blob** (#601): the width a pen is set to is about the width ordinary writing gives. The fountain pen goes from half of it at the lightest touch to one and a half times at the hardest, a little thinner when fast (15 %) and along its nib (25 %), with pointed ends 1.5 and 2 pen widths long; the brush from a quarter to 1.8 times (0.3 to 2.4 times after #608, below), up to 30 % thinner when fast, with ends 2 and 3 widths long. Whatever the pressure, speed, nib and tilt ask for, the width changes by at most 0.4 pt per point the pen travels (1 pt per point inside a pointed end), so a harder press, a pause or a turn shows as a swell and never as a blob; a pen held still swells slowly (as if moving 40 dp/s). The pointed end added on lift takes at most a third of the stroke. Only a dot (the pen moved less than one pen width) is given one even, full width on lift. With a finger the pressure is made from speed and stays in the middle 70 % of the pen's range: the middle at the pen's reference speed, heavier when slower, lighter when faster, levelling off instead of hitting an end. A sample that carries no pressure keeps the last one. Pen lab dials saved by an older build are dropped once (`pen_lab/dials.model`), because they were tuned against the older model; the pressure curve and the measured pressure range stay. The tail drawn from a pencil line to the pen is lightened by the ink density being laid down, so a light line is not led by a solid tip. Measured on made strokes in JVM tests only (`PenBlobTest`, `PenSheet`); nothing here has been checked on a phone yet.

**Points kept** (#609, step 1): a freehand line keeps a point every 0.75 dp on the glass (the same at every zoom), not every sample the pen gives (about 550 a second from an S Pen). A sample nearer than that is still kept where the line turns (leaving it out would move the line by more than 0.04 dp) or where the width has changed by 0.1 dp, and the last sample is always kept on lift. The pen model works on every sample as before; the tail to the pen covers the gap while writing. On the test sheet 2,056 samples become 698 points, and every sample stays within 0.1 dp of the thinned line, centre and edge (`InkThinningTest`). Shapes keep every point. Not measured on a phone, and the file size was not measured after the change.

**Pencil** (#569): graphite on paper. A light touch lays down less of it, so the paper shows through a fine grain; pressing harder fills it in (ink density 0.35 to 0.9 by default). Leaning the S Pen lays the side of the lead down: the line gets up to three times as wide and lighter. The grain is a fixed pattern of 0.3 pt dots on the page's grid, the same while drawing and in the saved comment, where each stroke stores its density per point (`/PCDensity`, beside `/PCWidths`) and is drawn per density step through a 1-bit image mask, so other PDF readers show the same grain. The eraser keeps the densities of what it leaves. The Pen lab's "Ink and paper" dials set the density range and how much leaning counts; at 1 the pencil is solid.

**A light hand in the middle of the pen, and a Pressure setting** (#608): a narrow measured pressure band is widened to twice its middle (at least 0.2, at most 0.35) and its ends are put at 10 % and 90 % of the pen's range. For a hand that writes at a raw pressure of 0.07 to 0.15 that is 0 to 0.22: its writing lands at about 0.36 to 0.65 of every pen (0.18 to 0.39 before), and the pen's top needs about 0.22 to 0.25 instead of 0.35. The brush now goes from 0.3 to 2.4 times its width on a steeper curve (1.8), so most of its change is above the middle: on the test sheet's word a light hand's brush line varies about 1.95 times between its 10th and 90th percentile and the fountain pen's about 1.45 times, both around the chosen width (median 1.01 and 0.97 of it). Each writing pen's popover has a **Pressure** slider (`ink.<style>.pressure`, 0 to 100 % in steps of 5, 50 % at first): how far the pressure the pen feels is moved away from the middle of the pen's range, from not at all (0 %: one width, the fountain pen's flat nib and the pointed ends stay; speed thins nothing) through the pen as it is (50 %) to twice (100 %). It is the same for a finger, whose pressure is made from speed. The marker has none. A favorite pen does not carry the setting. Measured on made strokes in JVM tests only (`PenPressureTest`); how it feels needs the owner's hand.

**Night Mode and dark paper** (#610): with Night Mode on, the ink being written is painted in the colour it will have once saved (the page's inverted grey: a black pen writes white on the black page), as are its tail, the zoom pad's paper, page and drafts, and the page shown under the live eraser. Before, drafts kept their own colours over the inverted page until they were saved, so a black pen wrote black on black. In a notebook made here with Dark paper, a pen still at its default colour writes light (white ballpoint, light grey pencil, light blue fountain pen, light red brush; each at least 4.5 to 1 against the paper), and its toolbar nib shows that colour; a colour the owner chose is never changed. The marker on Dark paper is painted opaque in its colour mixed with black, with the Lighten blend, on screen and in the saved comment (`comment_add` `backdrop: "dark"`, kept as `/PCBackdrop /Dark`): the paper takes the marker's colour, light ink under it stays light, and crossing strokes are still not laid down twice. With Darken the dark paper won everywhere and the marker drew nothing. Only notebooks made in the app with the Dark colour are known to have dark paper; any other dark PDF, and the reading colours with a black background, still get the Darken marker. Worked out as arithmetic in JVM and engine tests (`InkNightAndDarkPaperTest`, `a_freehand_highlighter_on_dark_paper_is_drawn_with_lighten`); not seen on a phone.

**Marker** (#569): flat (chisel) ends, drawn and saved. It is painted opaque in its colour mixed with white at its opacity, with the Darken blend: over white it looks as the colour at that opacity did with Multiply, text under it stays black, and where two marker strokes of one colour cross, or one crosses itself, the colour is not laid down twice, while drawing, after saving and in other PDF readers that blend. The comment keeps its colour and opacity (`/C`, `/CA`). **Straighten lines** in the marker's own popover (off by default): every marker stroke is shown and saved as a straight line from where it began to where it ended; a straight marker stroke over text still becomes a Highlight when Smart pen gestures is on.

Pen settings has two choices. **While the S Pen button is held**: Eraser (default, the earlier behaviour), Marker (that stroke uses the highlighter's own settings, then the selected pen is back) or Nothing. **S Pen button click while hovering**: Nothing (default), Undo, or Switch to previous pen. The mode of a stroke is decided at contact: pressing the button mid-stroke never cancels, splits or erases the stroke being written. The hardware eraser end always erases. A click is a press and release within 600 ms while the pen hovers without touching. Hover-click behaviour depends on the device reporting the button during hover and still needs checking on a Galaxy S Pen device.

## Writing hand and palm guard (#156)

Pen settings has **Writing hand** (Right or Left) and **Ignore palm while writing** (off by default) with a 60–240 dp area size. Choosing Left moves the quick rail to the right edge (it can still be dragged) and, on desktop layouts, puts the zoom buttons in the physical bottom-right corner in every language. With the guard on, a finger touch that starts inside the area beside and below the pen tip on the writing-hand side, within 1.5 s of the last pen hover or stroke sample, neither draws, scrolls, zooms nor counts as a two-finger tap; a pen arriving during that touch still writes. The area is drawn faintly while the pen hovers. The guard also covers the Draw toolbar and the quick rail: a finger touch that lands on them inside the guard area of a recently active pen is swallowed before any button sees it (the pen itself always gets through). **Check palm area**, under the size slider, opens a full-screen check: the guard area follows the hovering or writing pen, each finger touch is marked green (ignored) or red (it would act), and the size and writing hand can be adjusted there. The quick rail's side is physical (left or right of the screen) and its drags are physical, so an Arabic (right-to-left) interface and a left-handed writer combine correctly. Pen pickers open as full-width bottom sheets, so they have no side to mirror. Not built: a compact pen bar that follows the writing position on large tablets (a proposal in #156, not one of its acceptance items).

## Ruler (#150)

Draw ▸ **Ruler** shows a screen-space ruler with 5 dp ticks and its angle. One or two fingers on the ruler move it; two fingers also turn it about their centre. The angle snaps to 15° steps within 2° with a haptic tick. A freehand pen or finger stroke that starts within 24 dp of an edge follows that edge for the whole stroke (offset by half the stroke width), so the saved ink is straight. The ruler is only an overlay: it is kept per open document while it stays open and is never written to the PDF, exports or prints.

**Protractor**: Draw ▸ **Protractor** shows a half disc with 1°, 5° and 10° ticks and labels every 30°; one or two fingers move it, two turn it (snapping to 15° with a haptic tick, like the ruler). A freehand stroke that starts within 24 dp of its arc follows the circle for the whole stroke, so arcs of any length (even a full circle) are exact; a stroke that starts on its centre draws a straight ray whose direction locks to a whole degree once the pen leaves the centre. While drawing, a label beside the pen shows the ray's angle or the angle the arc has swept. A stroke that follows the ruler or the protractor is never changed into another shape by holding at its end, so hold-to-snap and the guides do not fight. Like the ruler, the protractor is viewer-only.

## Smart pen gestures (#148)

**Smart pen gestures** in Pen settings is off by default. When on, a freehand stroke is classified only after lift, so the live stroke gains no latency. A zig-zag with at least four horizontal reversals deletes the unsaved strokes and the saved, unlocked Ink comments mostly (60 %) under it; unsaved strokes come back with one Undo, saved ones with the document's Undo. A straight marker stroke (within 8 % of its length, within 12° of horizontal) over a text line becomes a Highlight of those words in the marker's colour; a straight pen stroke within 4 pt below a line becomes an Underline. Anything else stays ink. Undo is two-step for those: the first Undo takes the highlight or underline back and puts the raw stroke back where it was, a second Undo removes the stroke, and Redo goes the other way. **Circle-then-hold**: a freehand loop (at least 12 pt across, ending within a fifth of its size of its start) held still at its end for a moment gives a haptic tick; on lift the loop is not kept as ink but selects the drafts and saved comments it encloses or crosses, exactly as the Lasso would, and Draw switches to Lasso so the selection can be moved, recoloured or deleted. With smart gestures on, a held closed loop therefore lassos instead of snapping to a circle; the Oval tool still draws circles.

## Zoom writing box (#130)

Draw ▸ **Zoom box** docks a 200 dp writing pad at the bottom of the page area and draws its frame on the page. The pad shows that part of the page (from the page's latest whole-page image) and its ink, magnified to the pad's width. Writing in the pad adds ink at the matching page points with the selected pen. Lifting the pen in the shaded right-hand fifth moves the box 60 % of its width along the line; past the right margin it goes to the start of the next line, and past the bottom to the next page (the view follows). **New line** jumps there directly; dragging the frame on the page with a finger moves it (a horizontal drag also sets where new lines start). The frame and pad are viewer-only. The pad's background starts from the page's whole-page image and, about 120 ms after the box settles, is replaced by a render of just the box's region at the pad's own magnification (one pixel per pad pixel, at most 24 pixels per point), so small print stays sharp; that render is not cached and is redone when the page changes.

## Low-latency ink (#128): removed

Draw had an experimental "Low-latency ink" switch that drew each new segment straight into the display's front buffer (`CanvasFrontBufferedRenderer`). It was measured on the owner's phone (SM-S928B, 0.0.31-beta (31012)): app-side latency p50 5 ms / p95 13 ms with it, against p50 4 / p95 5 ms without, and the display dropped from 120 Hz to 60 Hz while it was on. So it was not faster, and it was removed from Draw and from Scan Markup, together with the `graphics-core` dependency. Ink is drawn in the normal Compose frame only.

**Measuring it on a device.** Pen settings shows **Ink latency on this device**: the typical (median) and worst-5 % (95th percentile) time from a pen sample's event time to the app's draw call that shows it, over the last 512 pen samples (impossible values below 0 or over 1 s are dropped). Write a few lines, tap **Update**; **Reset** starts over. This is app-side latency only: the system compositor, scan-out and the panel add more after the draw call, so it compares the two paths but is not touch-to-photon latency, which still needs a high-speed camera. Finger strokes are not measured.
